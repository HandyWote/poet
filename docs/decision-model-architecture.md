# 决策记录：模型架构与配置（GPT 古诗模型）

**日期**：2025-08-19（按项目时间线）
**决策**：6 层 GPT 式 Transformer，d=512，8 头，block_size=128，共享输入/输出 embedding，参数量 ≈ 22.7M
**参考**：[nanoGPT](https://github.com/karpathy/nanoGPT)（模型结构、数据格式、训练方式均以其为蓝本）

---

## 1. 背景

数据准备已完成（提取 → 切分 → 词表 → 编码，见 `decision-vocab-threshold.md`），
`train.bin` / `test.bin` 已就绪（13,564,418 / 5,806,696 个 uint16 token id）。
下一步实现模型（`model.py`）、训练（`train.py`）、生成与评测（`generate.py`）。

## 2. 决策结果：模型配置

| 配置项 | 值 | 说明 |
|---|---|---|
| `vocab_size` | 7399 | 词表大小，运行时从 `vocab.json` 读取，不写死 |
| `block_size` | 128 | 视野：写一个字最多回看 128 个 token |
| `n_layer` | 6 | 层数：同一套结构叠 6 遍 |
| `n_head` | 8 | 头数：每层 8 双眼睛，每头 64 维 |
| `n_embd` | 512 | 容量：每个 token 的向量维度 |
| `dropout` | 0.1 | 防过拟合（小数据下标准值） |
| `bias` | False | 所有 Linear/LayerNorm 不带 bias（nanoGPT GPT-2 配置） |
| 权重共享 | 是 | 输出层 `lm_head` 复用输入字表 `wte` 的权重 |

## 3. 模型结构（每层 = 四零件模板，叠 6 次）

| 零件 | 作用 | 参数 |
|---|---|---|
| 注意力（QKV） | 写每个字时回看前文，算"谁相关、拿什么" | `c_attn` 512×1536，`c_proj` 512×512 |
| 加工层（MLP） | 每个字单独消化收到的信息（512→2048→512，4 倍惯例） | 512×2048 + 2048×512 |
| 归一化（LN）×2 | 训练稳定性 | 每层 2×512（无 bias） |
| 残差连接 | x = x + 子层(x)，让深网络可训练 | 无参数 |

位置编码用可学习的位置表（`wpe`），因果性用下三角 mask 实现（`register_buffer`）。

## 4. 参数量计算

记 V = 7399（词表），d = 512（容量），L = 128（视野），n = 6（层数）：

```
M = V·d + L·d + n·(12d² + 2d) + d + [lm_head 共享 = 0]
  = 7399×512 + 128×512 + 6×(3d² + d² + 8d² + 2d) + 512
  = 3,788,288 + 65,536 + 6×3,146,752 + 512
  = 22,734,848 ≈ 22.73M
```

其中每层：QKV 3d² + 汇总 d² + MLP 8d² + 两个 LN 2d（bias=False 时仅 weight）。
上一个决策文档中公式写作 `n×(12d²+4d)`（LN 按带 bias 计），差异 ~6K 参数，可忽略。
`lm_head` 与 `wte` 共享权重，不重复计数。**自测时用 `sum(p.numel() ...)` 核对，应为 22.73M。**

## 5. 各配置项的选取依据

### 5.1 数据决定的（不可随意改）

- **vocab_size = 7399**：频率 ≥ 10 的字 + 3 个特殊符（见词表决策记录）。
- **block_size = 128**：数据中最长的诗（含标题）约 100+ 字，128 保证完整一首诗落在视野内。
  视野下限 = 最长样本长度，上限 = 算力预算（注意力复杂度随长度平方增长）。
  泛文本场景：先画文章长度分布，取覆盖 95% 的 2 的幂；过长文章切段喂、短文补空白。

### 5.2 惯例决定的（验证过不出错的默认值）

- **n_embd / n_head = 64**：2017 年 Transformer 原文 512/8=64 起，GPT-2 系列沿用。
  **注意：这是惯例不是铁律**——GPT-3 用 128 维/头，Llama 用 128 维/头；
  实测（Michel et al. 2019）训练后剪掉大部分头损失很小，头数远不如总容量重要。
  只要每头维度落在 32~128 的中间地带，都可用。
- **MLP 中间层 4 倍**：Transformer 原文所选，全行业沿用（Llama 等有微调）。
- **dropout 0.1~0.2**：小数据防过拟合的标准区间，nanoGPT 莎士比亚例用 0.2，本项目取 0.1。
- **pre-norm + 残差**：先归一化再进子层，nanoGPT 的 GPT-2 风格。

### 5.3 权衡决定的

- **n_layer = 6、n_embd = 512**：与数据量匹配的"偏大"配置，理由见 5.4。
- **模型明显大于 Chinchilla 建议（22.7M vs ~0.7M）**：有意为之，见 5.4。

### 5.4 为什么模型"超标"（重要决策）

- 经验法则（Chinchilla，DeepMind 2022）：**最优参数量 ≈ 训练 token 数 / 20**。
  本数据 13.5M token → 建议 ~0.68M 参数。该法则回答的问题是"固定算力预算下最划算",
  默认算力紧张。
- 本项目处境相反：**数据固定、算力富余**（笔记本可训数小时）。此时适用另一条实测规律
  （Kaplan 2020 缩放定律）：数据固定时，在过拟合之前，更大的模型能从同样数据学到更低损失。
- 现实原因：0.68M 参数的模型小到不像 Transformer（6 层×128 宽已 ~2.1M），学习价值低。
- 风险与对冲：超标必然过拟合（训练损失低、验证损失高）。对策 = dropout + 监控验证损失 + 早停。
- 代价：若目标是"最小算力拿到最优测试分数"，应改用 ~2M 参数的小模型——本项目选的是学习目标。

## 6. 实现规范（model.py）

- 类结构（自底向上）：`LayerNorm` → `CausalSelfAttention` → `MLP` → `Block` → `GPT`
- `GPTConfig` dataclass 集中所有数字，改配置只动这一处
- 注意力：QKV 三合一矩阵 `c_attn`（512×1536）后 `.split(n_embd, dim=2)`，reshape 成
  `(B, n_head, T, 64)`；相关度 `q@kᵀ / √64`；下三角 mask 遮未来；softmax；加权取值；
  transpose 后必须 `contiguous()` 再 `view`
- 因果 mask 用 `register_buffer`（否则不随 `.to(device)` 迁移）
- 权重共享：`lm_head.weight = transformer.wte.weight`
- 初始化：GPT-2 风格（std=0.02；残差投影按 `0.02/√(2·n_layer)` 缩小）
- 自测（项目根目录 `uv run model.py`）：
  - 参数量 = 22.73M
  - 随机输入 (2, 128) → logits (2, 128, 7399)
  - 随机权重 loss ≈ ln(7399) ≈ 8.909（乱猜的理论值，用于排错）

### 6.1 为什么手写而不是 `nn.Transformer`

PyTorch 有现成高层 API（`nn.TransformerEncoder` 5 行建好），但：
1. 它只覆盖"中间部分"，字表、位置表、输出头、因果 mask、权重共享仍需手写；
2. 其默认行为按机器翻译设计（post-norm、mask 格式、cross-attention），与 GPT 习惯不同；
3. 手写版每行对应 5.2/6 的每个零件，可调试、可学习。
`nn.Transformer` 内部干的事与手写版完全相同，只是封装程度不同。

## 7. 讨论记录：疑问与解答（FAQ）

以下为本项目讨论过程中提出的疑问及结论，供日后回顾。

**Q1：nanoGPT 是什么？参数为什么跟它一样？**
Karpathy 的极简 GPT 复刻（model.py + train.py 各 ~300 行），专为教学和快速 hack 自己的数据
而写，可在 MacBook 上训练。本项目数据格式与模型结构均以它为蓝本。

**Q2：这些数字（6 层、8 头、512、4 倍）是推导出来的吗？**
不是。结构有历史原因（每个零件解决一个具体问题，见 Q9），数字没有——是硬件预算 + 惯例。
512 的历史：2017 年论文作者只有 8 块 GPU，"512 是当时扛得动的最大号"（论文里 1024 版本
效果更好但更慢）。后来的 GPT-2/GPT-3 只是硬件变便宜后把同一模板放大，结构没变。

**Q3：层数为什么是 6？"小模型"的适用边界？**
经验值：数据量决定总参数量上限（≈ tokens/20），层数/宽度怎么分这笔预算没有定论。
粗估：1M 字 ~2-4 层，10M 字 ~4-6 层，100M 字 ~8-12 层。"小模型"无精确分数线，
大致指一台电脑几小时能训完（~10M~100M 参数量级）。想知道 4/6/8 哪个好，只能各训一遍比验证损失。

**Q4：每头 64 维、8 头是"甜点"吗？**
不是，之前口头说法不准确，以此文档为准。8×64 只是被大量项目验证过的默认值：
2017 年原文 512/8=64，GPT-2 沿用；GPT-3/Llama 用每头 128 维同样成功。
约束只有两端：头太少容量不足，头太多每头维度太小（<32）且浪费算力。

**Q5："脑细胞"（参数）是什么？**
模型 = 一个巨大数学公式，参数 = 公式里 2200 万个可调数字（旋钮）。
训练 = 反复微调旋钮：猜错下一个字就调一点，1300 万次猜字后旋钮收敛到能写诗的状态。
模型比数据大（22.7M 旋钮 vs 13.5M token）= 容易背答案（过拟合）。

**Q6：为什么 Shakespeare 1M 字配 10M 参数（超 200 倍）？**
与 Q5/5.4 同理：nanoGPT 目标不是"每单位算力最优"，而是"3 分钟训完、效果像样"。
作者注释明说"我们预期会过拟合"，配套 dropout=0.2 + 验证集变好才存模型。

**Q7：河流法（全语料连成一条流随机切窗口）还是按文章切？**
有 `<bos>/<eos>` 后两者差别很小，河流法更省事。业内从零预训练默认河流（packing，
文章长短不一，河流能 100% 利用算力）；微调按文章切（每个样本必须完整独立）。
nanoGPT 的莎士比亚本就是一条流。

**Q8：注意力为什么是三个矩阵（QKV）？**
"看前文"拆成两件事：判断谁相关（Q=我在问什么，K=前文是什么，二者相乘得相关度）
和决定拿什么（V=前文能给出的内容）。K/V 分离是因为"相关但没内容"和"不相关但有内容"
必须能分别打分。QKV 概念借自数据库检索（Query/Key/Value）。

**Q9：为什么注意力后面还要 MLP？**
注意力只做"搬运"（位置间交换信息），不改变信息本身；MLP 让每个位置单独"消化"。
这一层有数学硬理由：没有非线性加工，所有矩阵相乘会塌缩成一个线性映射，模型失效。

**Q10：为什么 MNIST 手写识别那么简单，GPT 这么复杂？**
任务形状不同：MNIST 是固定 28×28 格子、顺序无所谓、全图一次看完，Linear+ReLU 足够；
GPT 是长度不定的序列、顺序即语义、必须动态决定"回看哪些前文"。
复杂度只多一个东西：注意力层。GPT 骨架与 MNIST 相同（输入层 → 若干层 → 输出层），
只是中间那层从 `Linear+ReLU` 换成了 `注意力+加工`。

**Q11：为什么 PyTorch"应该很简单"却要写这么多？**
PyTorch 的简单在于**自动求导**（`loss.backward()` 一行算完所有梯度），这是 train.py 的活。
"模型长什么样"（model.py）和"怎么喂数据"（train.py）没人替你干。
用 `nn.Transformer` 高层 API 可以少写代码，但零件一个不少（见 6.1）。

**Q12：大模型公司研究员每天都在试参数吗？**
不是。架构全行业同一套模板；模型大小用缩放定律（实测曲线）按算力预算算出；
训练超参多为自动搜索；真正的研究是发明新结构，用对比实验（单变量、控变量）验证。
"改一个变量、量一次结果"就是研究员的基本工作方法，与后端 EXPLAIN 调 SQL 同理。

**Q13：训练"方法论"是什么？怎么获得？**
ML 的方法论 = 损失曲线诊断 + 单变量实验：
```
loss 不降了？
├─ 训练损失高 + 验证损失高 → 学得不够 → 加容量/加数据/多训/调学习率
├─ 训练损失低 + 验证损失高 → 背答案了 → 减容量/加 dropout/早停
└─ 两者都低但效果差 → 采样/任务定义问题
```
方法论无法靠阅读获得，只能靠亲手"改一个数字 → 看到损失变化"内化。
推荐教程：Karpathy《Neural Networks: Zero to Hero》（karpathy.ai/zero-to-hero.html，
含 *Let's build GPT* 一讲，与本项目同源）、李沐《动手学深度学习》（d2l.ai）。

**Q14：编程语言里的 "token" 和词表 "token" 是什么关系？**
同一个词、同一个概念：把字符流切成有意义的最小单位。Python 解释器执行前先把源码
切成 token（词法分析）；分词器把"床前明月光"切成字。`import`/`if` 这类叫关键字
（保留字），`print` 只是内置函数名（普通标识符，非保留）。
